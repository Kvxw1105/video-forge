### 1. 最严重的 N 个问题

#### P0 · 输入字段无防抖导致 API 雪崩

| 字段 | 内容 |
|------|------|
| 🎯 现象 | 在标题/水印输入框中每敲一个字母就触发一次 `PUT /api/projects/{id}`。用户在错误日志中留下了 **30+ 次连续 500 报错**，全因 onTitleChange 被连续高频调用 |
| ❓ 为什么是问题 | 用户正常输入"我的视频"需要敲 4 个键 → 触发 4 次 API → 4 次 JSON 序列化 → 网络正常时还行，但一旦 network lag 或后端过载，雪崩效应直接打崩接口。且 API 响应较慢时 UI 卡死，输入框失去响应 |
| 👤 用户期望 | 输入文字时丝滑流畅，只有在停止输入或失焦时才保存 |
| 💡 建议修改 | 所有 `onChange → update()` 调用改为 **300ms debounce** 或 **onBlur 时保存**。推荐使用 `use-debounce` 或 `lodash.debounce`，或者用 `onBlur` 触发更新而非 `onChange` |
| ✅ 验收标准 | 快速连续输入 20 个字符，API 调用不超过 3 次 |
| 📦 参考方案 | `lodash.debounce` / `use-debounce` npm 包 / 原生 `onBlur` |

#### P1 · 画布调整功能半成品

| 字段 | 内容 |
|------|------|
| 🎯 现象 | fit（适配/裁切/拉伸）三个按钮存在，但 `onClick` 是空函数（注释写着"这里暂时只记录"）。缩放滑块能拖动但每次调整都触发同步 API，导致滑块卡顿。**完全没有图片位置（x/y）调整** |
| ❓ 为什么是问题 | 用户看到的三个可点击按钮却没有任何效果——比没有按钮更糟，因为它**消耗用户信任**。缩放滑块每次拖动都发 PUT 请求，用户松开前已触发 5-10 次 API，体验极差 |
| 👤 用户期望 | 所有可见的交互控件都应能工作。缩放滑块应本地响应后批量保存，fit 点击应立即生效 |
| 💡 建议修改 | 1) fit 按钮补全实际逻辑，调用 `update` 更新 segment.transform.fit<br>2) 缩放滑块改为 localStorage 暂存 + 松开滑块的 `onMouseUp` 才存后端<br>3) 添加 x/y 位置微调按钮（上/下/左/右/居中） |
| ✅ 验收标准 | fit 切换立即反映在画布上；拖动缩放滑块不产生 API 调用 |
| 📦 参考方案 | 本地状态 + useEffect 去抖同步 |

#### P1 · BGM 文件选择功能不可用

| 字段 | 内容 |
|------|------|
| 🎯 现象 | `AudioPanel.tsx` 第 8 行：`onBgmChange(file.name)`——只传了文件名，没有实际上传逻辑。后端 `bgm.file` 被赋值为 `"song.mp3"` 这样的文件名，导出时路径解析失败 |
| ❓ 为什么是问题 | 用户选择 BGM 后 UI 显示"已选择"，但实际导出时文件找不到，剪映草稿中 BGM 轨道静音。用户会认为功能是坏的 |
| 👤 用户期望 | 选择 BGM 文件后上传到项目目录，导出时使用绝对路径 |
| 💡 建议修改 | BGM 选择后调用 API 上传到 `assets/` 目录，再保存完整路径到 `bgm.file`。复用现有 `uploadAsset` 端点 |
| ✅ 验收标准 | 选择 BGM mp3 文件 → 上传到项目 assets/ → 存储在 `bgm.file` → 导出时路径有效 |
| 📦 参考方案 | 复用 `POST /api/projects/{id}/assets` 上传端点，与图片素材共用 |

#### P1 · 导出草稿 ZIP 文件名固定

| 字段 | 内容 |
|------|------|
| 🎯 现象 | 每次导出都下载 `draft.zip`，无项目名区分。`Content-Disposition` 中 filename 硬编码 |
| ❓ 为什么是问题 | 用户同时做多个项目，导出后浏览器里 5 个 `draft.zip`，分不清哪个是哪个 |
| 👤 用户期望 | 导出文件名为 `{项目名}_draft.zip` |
| 💡 建议修改 | 在 `export.py` 中使用 `project.name` 构造文件名，并做 sanitize（去掉非法文件名字符） |
| ✅ 验收标准 | 导出下载的文件名为 `高考志愿_draft.zip` |
| 📦 参考方案 | `re.sub(r'[<>:"/\\|?*]', '_', project_name) + '_draft.zip'` |

### 3. 给开发 Agent 的修改任务

#### Task 1: 所有输入字段添加防抖

- **目标**：输入 title/watermark/text 时不再每次按键都触发 API
- **具体改动**：
  - 在 `useProject` hook 或 Editor 组件中引入 debounce 机制
  - title / watermark 的 `onChange` 改为 300ms debounce
  - 或改用 `onBlur` 触发更新（最简单的方案）
- **涉及文件**：`frontend/src/pages/Editor.tsx`、`frontend/src/hooks/useProject.ts`
- **交互细节**：用户在输入框中流畅打字，停止输入 300ms 后自动保存
- **状态处理**：保存中在输入框旁显示浅色"保存中..."，保存成功后消失
- **验收标准**：快速输入 20 个字符，API 调用不超过 3 次
- **测试建议**：手动在输入框快速输入，观察 Network 面板的 PUT 请求数

#### Task 2: 补全画布调整功能

- **目标**：fit 按钮生效，缩放滑块不卡顿
- **具体改动**：
  - fit 按钮绑定实际更新逻辑：`update({ segments: [{ ...seg, transform: { ...seg.transform, fit: newFit } }] })`
  - 缩放滑块改为本地 useState + `onMouseUp`/`onChangeCommitted` 时才触发更新
  - 添加 x/y 位置调整（微调按钮：左移/右移/上移/下移/居中）
- **涉及文件**：`frontend/src/components/canvas/CanvasPreview.tsx`、`frontend/src/pages/Editor.tsx`
- **交互细节**：点击"裁切"按钮 → 画布中图片立即从 contain 变为 cover 显示
- **状态处理**：本地状态即时响应，后台异步更新
- **验收标准**：fit 按钮点击后 canvas 绘画方式变化；缩放滑块拖动过程中不发请求

#### Task 3: BGM 文件上传功能

- **目标**：选择的 BGM 文件实际上传到服务端
- **具体改动**：
  - `AudioPanel` 选择文件后调用 `POST /api/projects/{id}/assets` 上传
  - 保存返回的完整路径到 `bgm.file`
- **涉及文件**：`frontend/src/components/panels/AudioPanel.tsx`
- **交互细节**：选择文件 → 上传指示 → "已选择 xxx.mp3"
- **状态处理**：uploading / uploaded / error
- **验收标准**：BGM 文件出现在 `projects/{id}/assets/` 目录中，导出时路径有效

#### Task 4: 导出文件名包含项目名

- **目标**：下载 ZIP 时文件名包含项目名
- **具体改动**：`export.py` 中 `Content-Disposition` 使用 `project.name`
- **涉及文件**：`backend/routers/export.py`
- **验收标准**：导出后下载文件名为 `项目名_draft.zip`

#### Task 5: AssetPanel 显示真正缩略图

- **目标**：上传图片后 AssetPanel 和 CanvasPreview 显示实际图片而非图标
- **具体改动**：
  - AssetPanel 上传后通过 `<img>` 标签渲染缩略图（使用后端 serves 的 URL）
  - CanvasPreview 的 image 加载路径需兼容 assets/ 子目录
- **涉及文件**：`frontend/src/components/panels/AssetPanel.tsx`、`frontend/src/components/canvas/CanvasPreview.tsx`
- **验收标准**：上传图片后 AssetPanel 和 CanvasPreview 都显示实际图片

#### Task 6: 添加 Toast 通知系统

- **目标**：操作成功/失败有非侵入式反馈
- **具体改动**：
  - 引入 Sonner 或手写简单 Toast 组件
  - 添加"配音生成成功""导出成功""保存失败"等通知
- **涉及文件**：新文件 `frontend/src/components/ui/Toast.tsx` + 在 `Editor.tsx` 中集成
- **验收标准**：配音完成后右下角闪现绿色 Toast"配音已生成 ✓"

| 错误 | 当前是否出现 |

### 7. 后端值得保留的架构亮点

不全是坏消息——以下架构决策值得保留：

- **project.json 作为唯一真相源**：数据模型和持久化方式合理，嵌套 Pydantic 模型层次清晰
- **双引擎配音架构**：Edge TTS / Manbo VIP 可插拔，`engine` 参数控制，符合设计文档
- **适配器输出模式**：JianYingAdapter 独立，与核心模型解耦
- **FFmpeg 分段合成**：多段音频拼接方案合理，支持超长文本
- **pyJianYingDraft 作为剪映格式桥接**：不自行逆向剪映格式，依赖成熟开源库
- **前后端分离 + REST API**：接口清晰，方便后续扩展
