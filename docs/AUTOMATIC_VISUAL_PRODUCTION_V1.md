# Automatic Visual Production v1

This branch delivers the first end-to-end vertical slice for automatic visual production:

`VisualPlan Scenes → local Visual Provider → PNG candidates → approval → canonical Project assets → existing timeline compiler → Preview/JianYing`

## Local Stickman Provider

The `stickman` provider is deterministic and local. It receives a read-only `SceneRequest` containing the existing Scene timing, subtitle IDs, prompt, and `inputHash`. It returns a PNG candidate plus an SVG source sidecar. It never edits Project, VisualPlan, subtitles, or timing.

Use the Factory panel's **本地 Stickman（零额度）** channel to generate candidates without an external image/video model quota. The output still goes through the normal candidate approval step. Approved assets are canonical Project image assets with provenance metadata (`providerId`, `providerVersion`, `inputHash`, and sidecar paths).

## Provider contract

Providers implement `backend/visual_providers/contracts.py`:

- `SceneRequest`: canonical input facts; timing is read-only.
- `ProviderResult`: media bytes, provider metadata, optional sidecars, and the original `inputHash`.
- `backend/visual_providers/registry.py`: lazy provider registry. Add providers without creating a second Project or Timeline model.

## Stale and regeneration behavior

Every batch stores the VisualPlan source hash and a per-Scene input hash. If the current Project/VisualPlan no longer matches, the batch becomes `stale` and generation/approval is rejected. Failed items can be retried; a single Scene can be regenerated by creating a batch with `sceneIds` containing only that Scene.

## Verification evidence

The local vertical slice was verified with three timed Scenes: real PNG files were generated and approved, the canonical compiler preserved the windows `(0,2)`, `(2,4)`, `(4,6)`, FFmpeg produced a non-empty MP4, and `ffprobe` reported `6.000000` seconds. The existing JianYing exporter produced a draft directory from the same canonical view.
